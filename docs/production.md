# Production

How production is put together and how to stand it up from nothing, following
[ADR-0015](adr/0015-production-host.md). Everything except the bootstrap below is OpenTofu in `infra/`. The
devshell (`nix develop`) has `tofu`, `aws` and `skopeo`.

```text
browser ──HTTPS──▶ Cloudflare: Worker "pioneer-edge" on <domain>     apps/edge, infra/cloudflare.tf
                     │  edge cache for hashed assets
                     │  SigV4-signed request
                     ▼
                   Lambda Function URL (AWS_IAM, RESPONSE_STREAM)     infra/aws.tf, ap-southeast-2
                     ▼
                   Lambda Web Adapter ─▶ pioneer-api on :3000          the image (ADR-0012)
                     │  direct (session) connection, TLS
                     ▼
                   Neon Free, aws-ap-southeast-2, Postgres 18          infra/neon.tf
```

## What runs where

| Piece                | Where                                                     | Created by                         |
| -------------------- | --------------------------------------------------------- | ---------------------------------- |
| Domain, TLS, DNS     | Cloudflare zone; the Worker's custom domain               | `cloudflare_workers_custom_domain` |
| Edge proxy and cache | Worker `pioneer-edge` (Workers Free, 100k requests a day) | `cloudflare_workers_script`        |
| API and web app      | Lambda `pioneer-api`, arm64, 512 MB, image from ECR       | `aws_lambda_function`              |
| Images               | ECR `pioneer-api` (last 5 kept), copied from GHCR         | `aws_ecr_repository`               |
| Logs                 | CloudWatch `/aws/lambda/pioneer-api`, 14 days             | `aws_cloudwatch_log_group`         |
| Database             | Neon project `pioneer`, database and role `pioneer`       | `neon_project`                     |
| OpenTofu state       | R2 bucket `pioneer-tofu-state`, encrypted client-side     | Bootstrap, by hand                 |

Lambda only runs single-architecture images from ECR in its own account; it cannot pull from GHCR or run the
multi-arch index. Every deploy therefore copies the arm64 image from GHCR to ECR with `skopeo`.

### Secrets

None are committed. Each lives in one place and reaches the runtime through OpenTofu:

| Secret                                  | Source of truth                              | Reaches                                                |
| --------------------------------------- | -------------------------------------------- | ------------------------------------------------------ |
| Database password (in `DATABASE_URL`)   | Generated by Neon                            | Lambda environment (encrypted at rest); deploy role    |
| OAuth client ids and secrets            | Password manager → `TF_VAR_oauth`            | Lambda environment; deploy role                        |
| Worker's IAM access key                 | Generated by `aws_iam_access_key.edge`       | Worker secret bindings                                 |
| State passphrase                        | Password manager → `TF_VAR_state_passphrase` | OpenTofu only                                          |
| Cloudflare token, Neon key, AWS profile | Password manager                             | OpenTofu only (`CLOUDFLARE_API_TOKEN`, `NEON_API_KEY`) |

The deploy role (`pioneer-deploy`) can read the whole function environment, since reading or updating a function
returns it; deploys use only `DATABASE_URL` and `PUBLIC_ORIGIN`, and mask the first.

State holds the generated secrets, so it is encrypted with the passphrase before it is written to R2
(`encryption` in `infra/versions.tf`). Losing the passphrase loses the state, not the resources.

### Caching

The API sets `Cache-Control` ([`apps/api/src/spa.ts`](../apps/api/src/spa.ts)): content-hashed files are
`public, max-age=31536000, immutable`, and `index.html` and everything else is `no-cache`. The Worker keeps a GET
response in the colo's cache only when it is a 200, is marked `public` with a non-zero `max-age` or `s-maxage`, is
not `private`, `no-store` or `no-cache`, and sets no cookie. So hashed assets are served from the edge after the
first request in each colo, and `index.html` and API responses always come from Lambda, which means a deploy is
live at once. Plain HTTP is redirected to HTTPS in the Worker before anything reaches the API.

## Bootstrap (once)

1. **Accounts.** An AWS account with an admin profile for applying; a Cloudflare account whose zone holds the
   domain, with R2 enabled; a Neon account.
2. **State bucket.** In Cloudflare, create the R2 bucket `pioneer-tofu-state`, then an R2 API token with Object
   Read & Write on that bucket only. Store its S3 keys as an AWS CLI profile:

   ```sh
   aws configure --profile pioneer-r2   # access key and secret from the R2 token; region: auto
   ```

3. **API credentials**, kept in the password manager:
   - Cloudflare API token with Account › Workers Scripts › Edit, Zone › Workers Routes › Edit, Zone › DNS › Edit and
     Zone › Zone › Read, limited to the account and the zone.
   - Neon API key (Account settings › API keys).
   - A state passphrase of at least 16 characters, for example `openssl rand -base64 32`.
4. **OAuth apps.** For each sign-in provider, register a production app with the callback
   `https://<domain>/api/auth/<provider>/callback` (GitHub, Discord and Google, as in `.env.example`).
5. **Local settings**, both gitignored:

   ```sh
   cd infra
   cp backend.hcl.example backend.hcl                 # R2 endpoint for your account
   cp production.tfvars.example production.tfvars     # domain, zone, account id, first image tag
   ```

6. **GitHub environment.** The deploy role (`infra/github.tf`) trusts any job in the repository's `production`
   environment, so limit that environment to `main` before the first apply creates the role:

   ```sh
   gh api -X PUT repos/DavidDudson/pioneer/environments/production \
     -F 'deployment_branch_policy[protected_branches]=false' -F 'deployment_branch_policy[custom_branch_policies]=true'
   gh api -X POST repos/DavidDudson/pioneer/environments/production/deployment-branch-policies \
     -f name=main -f type=branch
   ```

Every `tofu` command below runs from `infra/` with these in the environment, ideally injected by the password
manager rather than typed:

```sh
export AWS_PROFILE=<admin profile>
export CLOUDFLARE_API_TOKEN=... NEON_API_KEY=...
export TF_VAR_state_passphrase=...
export TF_VAR_oauth='{"github":{"client_id":"...","client_secret":"..."}}'   # providers left out are off
```

## First apply

The function cannot be created until its image is in ECR, and the API should not serve until the database is
migrated, so the first apply has three steps.

1. **Registry and database.** Pick the image to launch: the newest `sha-<short commit>` tag on
   `ghcr.io/daviddudson/pioneer`, which is set as `image_tag` in `production.tfvars`. Then:

   ```sh
   bunx nx build edge                        # dist/apps/edge/worker.js, which the Worker is created from
   tofu init -backend-config=backend.hcl
   tofu apply -var-file=production.tfvars -target=aws_ecr_repository.api -target=neon_project.pioneer
   ```

2. **Image and migrations.** Copy the arm64 image into ECR and migrate Neon with the same image:

   ```sh
   tag=sha-0000000                             # the image_tag above
   repo=$(tofu output -raw ecr_repository_url)
   aws ecr get-login-password | skopeo login --username AWS --password-stdin "${repo%%/*}"
   skopeo copy --override-os linux --override-arch arm64 \
     "docker://ghcr.io/daviddudson/pioneer:$tag" "docker://$repo:$tag"
   docker run --rm -e DATABASE_URL="$(tofu output -raw database_url)" \
     "ghcr.io/daviddudson/pioneer:$tag" migrate
   ```

3. **Everything else.** The function, Function URL, IAM, Worker and domain:

   ```sh
   tofu apply -var-file=production.tfvars
   ```

### Check it

```sh
curl -fsS "https://<domain>/api/health"                      # {"status":"ok"}
curl -s -o /dev/null -w '%{http_code}\n' "$(tofu output -raw function_url)api/health"   # 403: unsigned
curl -sI "http://<domain>/" | head -1                        # 301 to https
```

Then sign in with each configured provider. The first request after an idle spell takes a second or two while
Lambda starts the binary and Neon wakes (ADR-0015).

### Turn on deploys

Merges deploy through the GitHub `production` environment (bootstrap step 6), which allows `main` only. Once,
after the first apply, give it the deploy role:

```sh
gh variable set AWS_DEPLOY_ROLE_ARN --env production --body "$(tofu output -raw deploy_role_arn)"
```

Until `AWS_DEPLOY_ROLE_ARN` is set, the deploy job skips with a warning.

## Deploys

Every merge to `main` deploys: the Image workflow publishes `sha-<short commit>`, then calls `deploy.yml`, which
assumes `pioneer-deploy` over OIDC (`infra/github.tf`) and runs [`tools/deploy-production.ts`](../tools/deploy-production.ts).
One deploy runs at a time; a newer merge replaces a deploy still waiting, since its image includes those commits. It:

1. copies the arm64 image from GHCR to ECR, unless the tag is there already;
2. migrates Neon with that image (`pioneer-api migrate`), reading `DATABASE_URL` from the function. This happens
   before the new code takes traffic, so migrations must be safe while the previous image is still serving. It
   also seeds the image's official content packs (ADR-0029), under the same rule;
3. points `pioneer-api` at the image and waits for the update to finish;
4. checks `https://<domain>/api/health` through the Worker: 30 tries 2 seconds apart, each timing out after 10
   seconds. A failure fails the job.

The log names the image it replaced. OpenTofu ignores the function's image after creation, so later applies do not
roll a deploy back.

### Roll back

Deploy an earlier tag, from the Actions tab or:

```sh
gh workflow run deploy.yml -f tag=sha-1111111
```

or locally, with admin credentials and `docker login ghcr.io`:

```sh
bun tools/deploy-production.ts sha-1111111
```

ECR keeps the last five images; an older tag is copied from GHCR again. **Migrations are forward-only.** The
rollback runs the earlier image's migrate, which finds nothing to apply, and leaves the schema at the newer version.
The earlier code must therefore work with the newer schema: write migrations expand-then-contract (add columns and
tables first; drop or rename only once no deployed image reads the old shape). A migration that breaks that cannot
be rolled back by image; fix forward instead. Seeded content follows the same rule (ADR-0029): a rollback's migrate
writes its own packs back and leaves packs it does not ship as they are.

## Day two

- **Settings** (domain, memory, OAuth apps): change the variable and `tofu apply -var-file=production.tfvars`.
  Rebuild the Worker first (`bunx nx build edge`) whenever `apps/edge` changed, since the apply uploads
  `dist/apps/edge/worker.js`.
- **Rotate the Worker's AWS keys:** `tofu apply -var-file=production.tfvars -replace=aws_iam_access_key.edge`.
  The new pair is bound to the Worker in the same apply.
- **Neon limits.** Free suspends the database at 1 GB of storage, 5 GB of egress or 100 CU-hours in a month
  (ADR-0015). Usage alerts are #116; moving to Neon Launch is a plan change on the same project.
- **Backups** are nightly dumps to R2 (#115). Neon Free keeps only 6 hours of history.
- **Debugging.** Lambda logs are in CloudWatch (`aws logs tail /aws/lambda/pioneer-api --follow`); Worker logs are
  in the Cloudflare dashboard (observability is on).
