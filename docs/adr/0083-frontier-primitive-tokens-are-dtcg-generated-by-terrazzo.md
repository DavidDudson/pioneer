# 0083. Frontier's primitive tokens are DTCG files, generated to CSS by Terrazzo

- Status: Proposed
- Date: 2026-11-28

## Context

Frontier's tier 1 (colour ramps, spacing, type and duration scales) was a mix of a hand-written CSS file
(`primitives.scale.css`) and one generated by a 30-line script (`generate-ramps.ts`). Neither is readable by a design
tool, and the next colour work (12-step scales, generated damage and rune colours, an APCA gate) needs a source that
holds more than CSS can say about a token: its type, its role and the numbers it is built from.

The [Design Tokens Community Group format](https://www.designtokens.org/) reached its first stable version (2025.10)
and is read by Terrazzo, Style Dictionary, Tokens Studio and Figma exports. Options:

- **Keep the script.** No new dependency, but the source stays a private format and each new token kind grows the script.
- **Style Dictionary.** The most established DTCG tool, with a JavaScript transform pipeline.
- **Terrazzo** (chosen). DTCG-first, small, and its CSS plugin takes a `variableName` and a `transform` hook, which is
  enough to keep Pioneer's names and its theme-driven ramps.

## Decision

1. **`libs/frontier/src/tokens/primitives.tokens.json` is the source of tier 1**, in DTCG 2025.10: `ramp.<role>.<step>`
   colours and `scale.space`, `scale.font` and `scale.duration` steps.
2. **A ramp token holds the default theme's resolved colour**, so tools that read the file see real colours. Its
   `pioneer.ramp` extension holds the step's chroma as a fraction of the role's peak. The generated CSS does not
   use the resolved colour: it writes `oklch(L calc(var(--fr-ramp-<role>-chroma) * k) var(--fr-ramp-<role>-hue))`,
   because a theme sets each role's hue and peak chroma, so a theme is two numbers per role (themes stay in
   `src/styles/themes/`).
3. **`bun run tokens` generates `primitives.color.css` and `primitives.scale.css`**, configured in
   `libs/frontier/scripts/terrazzo.config.ts`. Variable names are unchanged (`--fr-ramp-accent-600`,
   `--fr-scale-space-3`), so the semantic tier and every utility are untouched.
4. **`bun run check:tokens` fails when the CSS is out of date** with the JSON. It runs in `lint:workspace`.
5. **The semantic tier (`semantic.css`) stays hand-written for now.** It holds mode logic and explanatory comments that
   a token file would lose, and the colour epic rewrites it to map fixed steps; generating it is decided there.

## Consequences

- The built CSS declares the same custom properties with the same values as before: this changes the tooling, not a
  pixel. The files are now alphabetical by role, and carry Terrazzo's banner.
- Two dev dependencies (`@terrazzo/cli`, `@terrazzo/plugin-css`) and one generated-file check.
- A theme's hue and chroma are in CSS and the default theme's colour is repeated in the JSON; the 12-step colour story
  decides whether themes move into DTCG too.
- Editing a ramp or scale means editing the JSON and running `bun run tokens`; the CSS is never edited by hand.
